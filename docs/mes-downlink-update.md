# 原同步程式更新：已確認訂單與製程下發

本次沿用 `sync_agent.py`、既有 Supabase `line_orders` 和原本三秒輪詢。新增的 `mes_dispatch.py` 是同一程式載入的模組，不是另一支服務。網站已改為先付款確認，再由管理者確認 MES 製程；工廠回傳 ONo 才算接收成功。

## 在工廠電腦更新

1. 在原同步視窗按 Ctrl+C 停止舊程式，備份原本的 `sync_agent.py`。
2. 更新需要 `sync_agent.py`、`mes_dispatch.py`、`mes_completion.py` 一起部署。在連線工廠電腦上修改時先建立副本，保留原可運作版本；同時只執行其中一份代理。2026-11-15 已完成本機 Python 副本部署，現場實際啟動位置見下方實測紀錄。
3. 保留工廠原有的 `FESTO_DB_PATH`、`SUPABASE_URL`、`SUPABASE_KEY` 設定和 `.env`。不要拿網站本機的 Access 快照覆蓋工廠資料庫。
4. 確認 MES4 已開啟。若同步程式與 MES4 在同一台電腦，預設使用 `127.0.0.1:2000`；否則把環境變數 `MES_HOST` 設成實際 MES4 電腦位址。`MES_PORT` 預設為 `2000`。
5. 在原本 Python 環境執行唯讀檢查：

   ```powershell
   python .\sync_agent.py --check
   ```

   應出現 `[CHECK OK]`。這只檢查資料庫、雲端讀取與 TCP 可連線，不建立 MES 工單，也不驗證實機生產。
6. 通過後照原方式啟動：

   ```powershell
   python .\sync_agent.py
   ```

`mes_dispatch_receipts.db` 會產生在原同步程式旁，用於記錄已送出的請求及工廠回覆。請保留此檔，不要刪除、另建空檔或用另一個目錄同時啟動代理。可用 `MES_DISPATCH_JOURNAL` 指定固定的可寫入路徑。

## 網站操作

到「管理 → 訂單 → 訂單明細 → 送至工廠 MES」。只有已確認、已同步雲端且沒有既有工單的訂單可以下發。為每個品項選擇 WPNo，再按「確認製程並送至工廠」。

- 黑／藍／白的未加工料號分別是 **210／410／610**；這些料號在所檢查的 MES 資料中 WPNo 均為 0，不能直接當成完整成品的製程。
- WPNo 必須已存在於工廠 MES。代理會核對固定製程、首站 ASRS 出料參數的原料色號，以及製程站點順序是否符合網站訂單。未對應或不相符不會送出建單指令。
- 不會自行改寫 MES 的加工參數或把黑色製程改成藍／白。若缺少匹配製程，先在 MES 確認正確的製程定義。
- 每個品項透過 MES 原生 `SetNewOrder` 建立工單，數量交由 MES 展開；混合品項可回傳多個 ONo，明細會列出各筆工廠回覆。
- `MES Ready v1`：已進入原雲端佇列，等待新版代理；`MES Dispatching:...`：代理正在處理；`In Production...` 且有工廠接收工單：已收到 MES 回覆；`MES Needs Review`：資料不匹配或接收結果未確認，須核對。
- 「重新讀取工廠接收結果」只讀取結果；「重試同步原請求」只重送同一份雲端請求，不產生另一張雲端訂單。

## 重送與舊訂單

送出 MES 指令前會持久記錄請求。收到 ONo 後即保存回覆；雲端回寫失敗只重試回寫，不重新建單。若斷線／程序中斷導致不知道 MES 是否已接收，會停止自動重送並顯示待核對。混合品項部分已接受時，會列出已接收的 ONo；不要把整單視為「完全未送出」。

MES4 此建單服務沒有網站請求唯一鍵，因此不能保證在「MES 已建立工單但回覆遺失」時自動恢復且不重複。需先檢查工廠現有工單和本機接收紀錄，再處理該請求；不要刪除接收紀錄來強迫重送。

舊版 `Confirmed` 或已有 ONo 的訂單不會批次重新下發，避免重複生產。新版只處理經網站管理者確認的 `MES Ready v1`。這也讓還沒更新的舊代理不會錯誤處理新版請求。

網站已移除結帳時直接建立 Access 表頭、網站自行編造雲端 ONo，以及用模擬完成時間改寫 MES 完工狀態的路徑。
