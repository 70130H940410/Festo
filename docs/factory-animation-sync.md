# 2D 工廠：沿用 MES 傳輸

管理者的 2D 工廠預設選擇「實際工廠同步」。資料路徑保持為：

`工廠 FestoMES.accdb → 原有 sync_agent.py → Supabase → 網站唯讀 API → Canvas`

沒有新增代理程式、背景派工、PLC 寫入或資料表；不啟動本機的同步代理來覆蓋工廠資料。

## 讀取與對應

- `GET /factory/api/floor_cloud_status?order_id=...` 沿用 MES 戰情室的管理者權限及 Supabase client。
- `tbl_machine_report`：Busy、ErrorL0/1/2、紀錄時間；Resource 1/2/3/4/5/6/7/8 對應 F/G/A/E/D/B/C/H。A 共用同一台倉儲，這份資料無法分辨 A1/A2。
- `order_list.mes_ono` → `tbl_order.ono`，再精確篩選 `tbl_fin_step.ono`。未對應不回退為本機模擬進度。
- 新紀錄且 Busy 為真時啟用加工示意；Busy 保持為真不重複單次動作。轉為閒置或故障就停止。動作的四秒為呈現用時間，不代表實測加工時間。
- 紀錄超過五分鐘、時間無時區、異常未來時間、讀取失敗或資料缺漏時，停止相關動畫。網頁每三秒嘗試更新，不重疊請求；請求二十秒逾時。工廠傳輸、查詢及輪詢時間都會造成延遲。
- 本機訂單進度及流程示範保留為另外兩個模式。

## 已知資料界線

原有代理只傳送機台狀態、工單、完成步驟與倉儲格位。`tbl_fin_step` 的識別鍵為 `(ono, step_no)`，沒有每件工件的序號；不能把一列當成一件工件。倉儲位置只代表儲位，不能用來推定輸送帶或搬運機器人上的位置。

目前不能確認每件工件所在站點、進出料交接點、R1/R2 身分與座標、載貨序號及新站狀態。因此實廠模式不產生推測的移動工件或 R 路徑；畫面標示定位未知。完整逐件搬運同步仍需確認工廠原系統的工件識別／位置／載貨欄位；若需要擴充，只擴充既有代理，不建立另一套傳輸。

原有代理沒有同步心跳，且狀態不變時可能不更新紀錄時間。舊紀錄不能證明工廠離線；連上 Supabase 也不能證明工廠此刻在線。
